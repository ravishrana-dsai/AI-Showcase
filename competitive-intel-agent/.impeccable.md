# [Company] CI Bot — Design Context

## Design Context

### Users
Primary: Solo power user (product/strategy lead at [Company]) running the tool daily.
Secondary: Leadership presentations — the dashboard gets screen-shared or demo'd to executives and investors. It must look authoritative and polished enough to present, not just functional enough to use.

### Brand Personality
**Bold · Analytical · High-signal**

The interface should feel like a war room: every pixel of data purposeful, nothing decorative, but with enough visual presence to command a room. Urgency without chaos. Authority without coldness.

### Aesthetic Direction
**Bloomberg Terminal meets Reuters newsfeed — but bigger, bolder, and more readable.**

- Dense data presented with confidence, not apology
- Strong typographic hierarchy: headlines shout, labels whisper
- Terminal-inspired section formatting: caps labels, left-border accents, high-contrast dividers
- NOT as cramped as Bloomberg (more breathing room, clearer hierarchy)
- Color as signal, not decoration: red = threat, green = positive, yellow = warning, blue = informational
- Dark theme only (command presence in presentations)

References: Bloomberg Terminal (information density, amber accents, monospace data), Reuters.com (editorial hierarchy, bold headlines, time-stamped feeds)
Anti-references: Generic SaaS dashboards (rounded cards everywhere, pastel gradients), "AI startup purple-glow" aesthetic

### Design Principles
1. **Every pixel earns its place** — no decorative elements, only purposeful ones
2. **Color means something** — consistent semantic use of red/green/yellow/blue throughout
3. **Data dominates, chrome recedes** — UI elements should fade, data should pop
4. **Bold hierarchy** — 4x size difference between stat numbers and labels; section headers are shouted in caps
5. **Presentation-ready at all times** — assume someone could look over your shoulder at any moment; the dashboard must always look authoritative
